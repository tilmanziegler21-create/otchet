# Отчеты по продажам — Telegram-бот

Бот для ежедневных отчетов по продажам. Работник вводит только количество и выручку
по категориям и число покупателей — бот сам считает средний чек, UPD, себестоимость
и чистую прибыль. Закупочные цены и вся внутренняя экономика доступны только
администраторам.

## Возможности

**Работник**
- «🆕 Новый отчет» — город кнопкой → дата (по умолчанию сегодня) → по каждому бренду
  количество, выручка и сколько клиентов его купили → всего покупателей за день →
  рассылки (касания, ответы, покупки, доп оборот);
- предпросмотр с кнопками «✅ Подтвердить» / «✏️ Исправить» (можно поправить любую
  категорию, число покупателей, рассылки или город);
- после сохранения видит только безопасную сводку: по каждому бренду штуки,
  клиентов и UPD, проданные жидкости, общий UPD, общую выручку и цифры рассылок;
- `/report_today`, `/reports` — свои отчеты без себестоимости и прибыли.

**Администратор** (`/admin`, только для ID из `ADMIN_IDS`)
- посмотреть текущие закупочные цены;
- установить закупочную цену категории;
- изменить закупочную цену;
- добавить новую категорию (название, закупочная цена, признак «жидкость»);
- управлять городами: добавить город, включить или выключить его, задать ставку
  работникам и план на месяц;
- посмотреть сводку за неделю или за месяц по городу (`/week`, `/month`);
- посмотреть сохраненные отчеты;
- автоматически получает полный финансовый отчет сразу после подтверждения работником.

## Формулы

| Показатель | Формула |
|---|---|
| Средний чек | `выручка / количество` (при количестве 0 — 0) |
| Себестоимость | `количество × закупочная цена` |
| Менеджеру | `общая выручка × 5%` — одинаково во всех городах |
| Работникам | процент от оборота, фикс за день или `фикс за месяц / дней в месяце` |
| Перевыполнение | `25%` от кассы месяца, превысившей план города |
| Чистая | `общая выручка − менеджеру − работникам − перевыполнение − себестоимость` |
| CARLGAUSS | `чистая / 4` |
| Остаток | `чистая − CARLGAUSS` |
| UPD | `проданные жидкости / количество покупателей` (2 знака) |
| UPD бренда | `количество бренда / клиенты этого бренда` (2 знака) |
| Ответили | `ответившие / касания × 100` |
| Перешли к покупке | `покупки / ответившие × 100` |

Жидкости — категории с признаком `is_liquid` (по умолчанию ELFLIQ и CHASER).
Итоговая чистая считается строго от общих сумм, по категориям — пропорционально
их выручке и себестоимости; выплаты людям (менеджеру, работникам,
перевыполнение) разносятся по категориям пропорционально выручке, поэтому сумма
прибыли категорий равна итогу.

Бонус за перевыполнение начисляется приростом: бот берет кассу города с начала
месяца по сохраненным отчетам и считает 25% от той части, что перешагнула план.
Пока план на месяц не задан, бонус равен нулю. Сумма бонуса и план сохраняются
в отчет снимком, поэтому старые отчеты не меняются.

Экономика вынесена в `services/calculations.py` — функции `calculate_manager`,
`calculate_salary`, `calculate_bonus`, `calculate_net_profit`,
`calculate_carlgauss` и `calculate_remainder`, плюс константы `CARLGAUSS_SHARE`,
`MANAGER_SHARE` и `BONUS_SHARE`. Чтобы изменить формулы, правьте только их.

## Установка и запуск

```bash
git clone <repo> && cd otchet
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # и заполнить BOT_TOKEN и ADMIN_IDS
python bot.py
```

### .env

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | да | Telegram ID администраторов через запятую (узнать: [@userinfobot](https://t.me/userinfobot)) |
| `DB_PATH` | нет | Файл SQLite, по умолчанию `bot.db` |
| `CURRENCY` | нет | Символ валюты, по умолчанию `€` |

База и категории ELFLIQ, CHASER, HQD, VOZOL создаются автоматически при первом запуске.
Закупочные цены изначально равны 0 — задайте их через `/admin`.

## Команды

- `/start` — регистрация и главное меню
- `/report_today` — отчет за сегодня
- `/reports` — сохраненные отчеты
- `/admin` — админ-панель (только для администраторов)
- `/week` — сводка за неделю по городу (только для администраторов)
- `/month` — сводка за месяц по городу (только для администраторов)
- `/cancel` — отменить текущее действие

## Деплой на Render

В репозитории есть `render.yaml` (Blueprint) — Background Worker с long polling
и постоянным диском для SQLite.

1. Запушить репозиторий на GitHub (или GitLab/Bitbucket).
2. Render → **New** → **Blueprint** → выбрать репозиторий → Apply.
3. Задать переменные `BOT_TOKEN` и `ADMIN_IDS` (в `render.yaml` они помечены
   `sync: false`, поэтому запрашиваются при создании и в репозиторий не попадают).

Что важно знать:

- Тип сервиса — **worker**, а не web service: боту не нужен HTTP-порт, он сам
  опрашивает Telegram. Бесплатного тарифа у воркеров нет, минимум Starter.
- Диск смонтирован в `/var/data`, `DB_PATH=/var/data/bot.db`. Без диска файловая
  система Render эфемерна и все отчеты исчезнут при первом же редеплое.
- Одновременно с Render нельзя держать запущенным локальный `python bot.py` —
  Telegram отдает обновления только одному опрашивающему клиенту, второй получит
  ошибку `409 Conflict`.
- Версия Python задана в `.python-version`.

Резервная копия базы: скачать `/var/data/bot.db` из шелла сервиса
(Render Dashboard → сервис → Shell).

## Добавление категории

Через `/admin` → «🆕 Добавить категорию»: название, закупочная цена, признак «жидкость».
Категория сразу появится в следующем отчете работника и в расчете UPD (если жидкость).

## Города

Через `/admin` → «🏙 Города» → «➕ Добавить город». Нажатие на город открывает его
карточку: там задается «минус работникам», план на месяц, и город включается или
выключается. Выключенный город не предлагается работнику, но остается в старых
отчетах.

«Минус работникам» задается для каждого города отдельно, одним из трех способов:

- «📊 Процент от оборота» — процент от дневной выручки города;
- «💶 Фикс за день» — фиксированная сумма за день;
- «🗓 Фикс за месяц» — сумма за месяц (например 1300€), в дневном отчете делится
  на число календарных дней этого месяца.

Ставка фиксируется в отчете в момент сохранения (`salary_kind_snapshot`,
`salary_value_snapshot`), поэтому ее изменение не пересчитывает старые отчеты.

«🎯 План на месяц» — план по обороту города на прошлый, текущий или следующий
месяц. Все, что касса месяца набрала сверх плана, дает работникам 25% бонуса за
перевыполнение (строка «ПЕРЕВЫПОЛНЕНИЕ» в отчете). План `0` убирает бонус.

5% менеджеру считаются от дневного оборота в каждом городе и не настраиваются —
доля лежит в `MANAGER_SHARE` в `services/calculations.py`.

Каждый отчет привязан к городу — работник выбирает его кнопкой в начале заполнения.
Город показывается в шапке отчета (`01.09 · Рига`) и в списках `/reports`, поэтому
отчеты разных точек не путаются. За одну дату можно сохранить по отчету на каждый
город; при повторном отчете по тому же городу и дате бот предупреждает.

Пока не добавлен ни один город, работник не сможет начать отчет — бот попросит
обратиться к администратору. Закупочные цены общие для всех городов.

## UPD по брендам

По каждому бренду работник вводит три числа: сколько штук продали, какая по нему
касса и сколько клиентов его купили. UPD бренда считается от его же клиентов
(`43 шт. / 28 клиентов = 1,54`), а не от общего числа покупателей за день.
Клиентов нельзя ввести больше проданных штук — бот попросит число заново.

Общий вопрос «сколько всего было покупателей» остался: от него считается общий
UPD по жидкостям. Сумма клиентов по брендам обычно больше этого числа, потому что
один покупатель мог взять несколько брендов.

Если по бренду продали 0 штук, бот не спрашивает ни выручку, ни клиентов.
В сводке за неделю и месяц клиенты бренда складываются за все дни, и UPD бренда
считается от этих сумм.

## Рассылки

После количества покупателей бот спрашивает по этому же городу и дате: сколько
было рассылок (касаний), сколько ответили, сколько перешли к покупке и какой
доп оборот они создали. Если касаний за день 0, остальные три вопроса
пропускаются. Поправить блок можно в предпросмотре кнопкой «📨 Рассылки».

Ответивших нельзя ввести больше касаний, а покупок — больше ответивших: бот
попросит число заново.

Доп оборот справочный — он уже сидит в выручке категорий, поэтому в общую
выручку второй раз не добавляется и на чистую, менеджера, работников и план не
влияет. В отчете он подписан «уже в общей выручке».

Цифры рассылок и UPD по брендам работник видит после сохранения — это не
внутренняя экономика. В недельной и месячной сводке касания, ответы, покупки и
доп оборот складываются за период, а конверсии считаются от этих сумм.

## Недельный и месячный отчет

`/admin` → «📅 Отчет за неделю» или «🗓 Отчет за месяц» (то же самое дают команды
`/week` и `/month`): сначала город, потом период — кнопками переключаются текущий,
прошлый и позапрошлый. Сводка видна только администратору.

Неделя — календарная, понедельник–воскресенье; месяц — с первого по последнее
число. Внутри сводки то же, что в дневном отчете: разбивка по категориям,
жидкости, покупатели и UPD за период, строка по каждому дню с выручкой,
количеством и числом покупателей, и итоги с выплатами и прибылью.

Выплаты за период не пересчитываются заново, а складываются из снимков дневных
отчетов, поэтому чистая за период равна сумме дневных чистых. Себестоимость тоже
суммируется по снимкам закупочных цен. Для Гамбурга это значит, что месячный фикс
попадает в сводку суммой по заполненным дням: заполнены все 30 дней — выйдет
1300€, заполнено 20 — выйдет 866,67€.

Периодные сводки собирает `build_period_summary` в `services/calculations.py`,
границы периодов — `period_bounds` в `services/report_service.py`.

## Хранение данных

Таблицы: `users`, `categories`, `cities`, `monthly_plans`, `daily_reports`,
`daily_report_items`.
В `daily_report_items.purchase_price_snapshot` сохраняется закупочная цена на момент
создания отчета — поэтому изменение цен администратором не меняет старые отчеты.
Схема догоняется автоматически при запуске: в базы прошлых версий добавляются
`daily_reports.city_id`, `bonus_snapshot`, `plan_snapshot`, колонки рассылок
(`touches`, `replies`, `purchases`, `extra_revenue`), таблица `monthly_plans` и
`daily_report_items.customers_count`; старые отчеты остаются без города, без
бонуса и с нулями по рассылкам и клиентам брендов.
