# Отчеты по продажам — Telegram-бот

Бот для ежедневных отчетов по продажам. Работник вводит только количество и выручку
по категориям и число покупателей — бот сам считает средний чек, UPD, себестоимость
и чистую прибыль. Закупочные цены и вся внутренняя экономика доступны только
администраторам.

## Возможности

**Работник**
- «🆕 Новый отчет» — дата (по умолчанию сегодня) → по каждой категории количество и
  выручка → количество покупателей;
- предпросмотр с кнопками «✅ Подтвердить» / «✏️ Исправить» (можно поправить любую
  категорию или число покупателей);
- после сохранения видит только безопасную сводку: проданные жидкости, UPD, общую выручку;
- `/report_today`, `/reports` — свои отчеты без себестоимости и прибыли.

**Администратор** (`/admin`, только для ID из `ADMIN_IDS`)
- посмотреть текущие закупочные цены;
- установить закупочную цену категории;
- изменить закупочную цену;
- добавить новую категорию (название, закупочная цена, признак «жидкость»);
- посмотреть сохраненные отчеты;
- автоматически получает полный финансовый отчет сразу после подтверждения работником.

## Формулы

| Показатель | Формула |
|---|---|
| Средний чек | `выручка / количество` (при количестве 0 — 0) |
| Себестоимость | `количество × закупочная цена` |
| 30% | `общая выручка × TAX_RATE` |
| Чистая прибыль | `выручка − 30% − себестоимость` |
| UPD | `проданные жидкости / количество покупателей` (2 знака) |

Жидкости — категории с признаком `is_liquid` (по умолчанию ELFLIQ и CHASER).
Итоговая чистая прибыль считается строго от общих сумм, по категориям —
пропорционально их выручке и себестоимости.

Формула прибыли вынесена в `services/calculations.py` — функции `calculate_tax`
и `calculate_net_profit`. Чтобы изменить экономику, правьте только их
(ставку 30% можно поменять через `TAX_RATE` в `.env`).

## Установка и запуск

```bash
git clone <repo> && cd otchet
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env               # и заполнить BOT_TOKEN и ADMIN_IDS
python bot.py
```

### .env

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен от [@BotFather](https://t.me/BotFather) |
| `ADMIN_IDS` | да | Telegram ID администраторов через запятую (узнать: [@userinfobot](https://t.me/userinfobot)) |
| `DB_PATH` | нет | Файл SQLite, по умолчанию `bot.db` |
| `TAX_RATE` | нет | Доля вычета из выручки, по умолчанию `0.30` |
| `CURRENCY` | нет | Символ валюты, по умолчанию `€` |

База и категории ELFLIQ, CHASER, HQD, VOZOL создаются автоматически при первом запуске.
Закупочные цены изначально равны 0 — задайте их через `/admin`.

## Команды

- `/start` — регистрация и главное меню
- `/report_today` — отчет за сегодня
- `/reports` — сохраненные отчеты
- `/admin` — админ-панель (только для администраторов)
- `/cancel` — отменить текущее действие

## Деплой на Render

В репозитории есть `render.yaml` (Blueprint) — Background Worker с long polling
и постоянным диском для SQLite.

1. Запушить репозиторий на GitHub (или GitLab/Bitbucket).
2. Render → **New** → **Blueprint** → выбрать репозиторий → Apply.
3. Задать переменные `BOT_TOKEN` и `ADMIN_IDS` (в `render.yaml` они помечены
   `sync: false`, поэтому запрашиваются при создании и в репозиторий не попадают).

Что важно знать:

- Тип сервиса — **worker**, а не web service: боту не нужен HTTP-порт, он сам
  опрашивает Telegram. Бесплатного тарифа у воркеров нет, минимум Starter.
- Диск смонтирован в `/var/data`, `DB_PATH=/var/data/bot.db`. Без диска файловая
  система Render эфемерна и все отчеты исчезнут при первом же редеплое.
- Одновременно с Render нельзя держать запущенным локальный `python bot.py` —
  Telegram отдает обновления только одному опрашивающему клиенту, второй получит
  ошибку `409 Conflict`.
- Версия Python задана в `.python-version`.

Резервная копия базы: скачать `/var/data/bot.db` из шелла сервиса
(Render Dashboard → сервис → Shell).

## Структура проекта

```
bot.py                      запуск, роутеры, команды меню
config.py                   чтение .env (BOT_TOKEN, ADMIN_IDS, TAX_RATE, ...)
render.yaml                  Blueprint для деплоя на Render
database.py                 SQLite: схема и все запросы
handlers/
  common.py                 /start, /cancel, fallback
  employee.py               FSM нового отчета, предпросмотр, сохранение
  admin.py                  админ-панель (закупки, категории, отчеты)
  reports.py                /report_today, /reports
services/
  calculations.py           формулы: средний чек, себестоимость, 30%, прибыль, UPD
  report_builder.py         тексты отчетов (полный / безопасный / предпросмотр)
  notifications.py          отправка полного отчета админам
keyboards/
  employee.py               меню работника, предпросмотр, исправление
  admin.py                  инлайн-меню админ-панели
utils/
  dates.py                  разбор и формат дат
  formatting.py             европейский формат сумм (13,28€) и разбор ввода
  access.py                 фильтры IsAdmin / IsNotAdmin
```

## Добавление категории

Через `/admin` → «🆕 Добавить категорию»: название, закупочная цена, признак «жидкость».
Категория сразу появится в следующем отчете работника и в расчете UPD (если жидкость).

## Хранение данных

Таблицы: `users`, `categories`, `daily_reports`, `daily_report_items`.
В `daily_report_items.purchase_price_snapshot` сохраняется закупочная цена на момент
создания отчета — поэтому изменение цен администратором не меняет старые отчеты.
